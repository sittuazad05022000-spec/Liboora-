## 1. Context

### 1.1 The blocker, as it stood

`H-B` is a **two-limb** act. `HD-1` §2.3's *Remaining dependency* line routes it, verbatim:

> **Owner:** Product Owner (domain) **with Architecture Owner concurrence per `ADR-0099` `C-3`**.

| Limb | State before this ADR |
|---|---|
| **Product Owner** — the per-field script bindings | ✅ **RECORDED** — `SRCHPO-17`, Supplement B: 3 of 3 `text`-role units bound to **Latin + Devanagari** |
| **Architecture Owner** — concurrence | ⛔ **NOT SUPPLIED** — ARB unseated; concurrence artefacts measured at **0** |

⭐ Rule `X3` — *"A gap closes on all limbs, not a majority"* — therefore held `H-B` **OPEN** at
**PO limb 8/8 · concurrence limb 0/1**.

### 1.2 ⭐ Why the preceding conferral could not supply it

`ADR-0102` conferred the **SRE / Observability** office and closed `H-D`. It expressly could **not**
travel to this act, and §6 of that ADR recorded why:

| Test | Result |
|---|---|
| Does `H-B` need SRE / Observability? | ⛔ **NO** |
| Which office does it need? | ⭐ the **Architecture Owner** = **ARB** (`PRD_OWNERSHIP_MODEL.md` **L197**) |
| `ADR-0054` **L148** | *"Those are **different roles**"* |

⭐⭐ **The `H-B`/`H-D` coupling was a SHARED BLOCKER, never a shared authority** — both awaited a
human conferral act, and `ADR-0102`'s named a different office. ⇒ A **separate** conferral was
required, and has now been made.

⛔ **The other 11 units of `SRCHPO-16` carry no script and none is added here** — every `exact`,
`filter` and `none` unit is untouched. **0 scripts assigned.**

### 3.2 ⭐ The four `ADR-0099` constraints the concurrence is tested against

⭐ **Concurrence is not a rubber stamp; it is a test.** Each constraint is checked against the
bindings as recorded, and the checks are the substance of this act:

| # | Constraint | Test result |
|---|---|---|
| **`C-3`** | *"MUST consume an authoritative declared script; MUST NOT detect script from content; index and query MUST use the same authoritative script source"* | ✅ **SATISFIED.** `SRCHPO-17` is a **declaration** carried by the `HD-1`-selected artefact; ⛔ **0 content-detection** is introduced. Index and query consume the **same** declaration — there is only one |
| **`C-8`** | *"MUST NOT presuppose a third canonical language or index"* | ✅ **SATISFIED.** Both values are members of `SRCHPO-1`'s closed set of two; Hinglish is placed **inside Latin** as query behaviour, adding **0** values |
| **`C-9`** | *"MUST NOT introduce a language-detection capability"* | ✅ **SATISFIED** — ⛔ **0** detection introduced |
| **`C-4`** | *"Normalization rules are applied according to the field's authoritative declared script"* | ⚠⚠ **SATISFIED AS TO INPUT, OPEN AS TO APPLICATION** — §4 |

⭐ **`C-1` (index/query symmetry) and `C-2` (totality/symmetry) are NOT satisfied by this act and are
not claimed to be** — they bind the **rule set**, which remains OPEN at `ADR-0099` §2.3. A binding
supplies `C-3`'s *input*; it does not author the rules that consume it.

### 3.3 ⭐ Why the cardinality question does not block concurrence

⭐ **The Product Owner record already tested it and this ADR adopts that measurement rather than
re-deriving it.** `SRCHPO-A9` (Supplement B §2.2) measured:

| Measurement | Result |
|---|---|
| `exactly one script \| single script \| one script per \| only one script` over `docs/` | ⭐ **0 relevant hits** |
| How the repository **does** state cardinality-one | `SRCH-AC-018` **L1066** — *"exactly one match role"* |

⇒ The singular articles in `C-3`, `C-4` and `HD-2` are **grammatical, not normative**. ⛔ **No
authority is breached by a two-member binding**, so there is no ground on which the Architecture
Owner could lawfully withhold concurrence — and ⛔ **none is manufactured to withhold it either.**

⭐ **`SRCHPO-A10` corroborates from a Rank-below-authority source that pre-dates the binding:**
`PRD-015_P2_ARCHITECTURE_DECISION.md` **L691** already contemplated *"a **mixed-script field value**
(a Hindi name containing a Latin acronym)"* — i.e. a **Library Name**, unit 1 — and recorded the
sub-question as *"unaddressed by any authority."*

## 4. ⚠⚠ `SRCHPO-A11` — the residual, CONFIRMED OPEN by the concurring authority

⭐⭐ **This is the section the conferring instruction expressly required, and it withholds rather
than grants.**

⭐ **What is concurred:** each of the three `text` units **admits** both members of `SRCHPO-1`'s
closed set. The **declaration** is complete for those units.

⛔ **What is NOT concurred and NOT invented:** by what **declared rule** the analyzer selects between
the Latin and Devanagari rule sets for a given token, with content-detection prohibited.

| Requirement | Authority | State after this ADR |
|---|---|---|
| Rule set **symmetric and total** | `SRCH-BR-008` (**L427-429**) | ⚠ **OPEN** — totality over a two-member script domain needs a per-rule disposition |
| Rules applied per the declared script | `C-4`; `HD-2` | ⚠ **OPEN as to content** — `HD-2` is *"MODEL CLOSED · RULE CONTENT OPEN"* |
| `N1` inapplicable to Devanagari | `HD-3` — SCRIPT-CONDITIONAL | ⭐ **already ruled**, and it is **per-rule**, not per-field — the shape a two-member binding needs |
| Script never derived from content | `C-3`, `C-9`, `SRCHAO-F5 = Option A` | ✅ **preserved — 0 detection** |

⭐⭐ **`HD-3` is why the two-member binding is coherent rather than incoherent, and this is a
coherence finding, not a mechanism.** `HD-3` conditions normalization **at the rule level**; a
per-rule conditional does not require the *field* to hold exactly one script — it requires each
**rule** to have a defined disposition. That disposition table is **Architecture-Owned and remains
OPEN**, routed at `ADR-0099` §2.3 to *"a later Architecture Owner act, evidence-bound."*

⛔⛔ **This ADR writes no disposition table, names no analyzer or tokenizer, and invents no
selection rule.** ⚠ **`SRCHPO-A11` is therefore recorded OPEN by the very office that owns it** —
which is a stronger record than an unowned gap, and is exactly what the instruction directed.
