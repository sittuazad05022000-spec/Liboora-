### 5.1 ⭐⭐ Why the baseline identifier does NOT change — measured against rule 4, not assumed

`DOCUMENTATION_BASELINE.md` **§7 rule 4**:

> *"The baseline identifier changes only when a **Rank 1–3 document changes version**."*

| Test | Result |
|---|---|
| Does any already-baselined Rank 1–3 document change version? | ⛔ **NO** |
| Is `PRD-015` v0.1 *changing* version? | ⛔ **NO** — it is **admitted at v0.1**, its first appearance; ⭐ its bytes are **unchanged** (`sha256` `fe3093e6…c2c4544`) |
| ⇒ Is a re-issue required? | ⛔ **NO** |

⚠ **Disclosed asymmetry, not hidden:** the `PRD-021C` admission *did* advance the identifier to
`BASELINE-2026-09-03-A`. ⭐ **The difference is measurable**: that pass also advanced the Bounded
Context Map and other Rank 1–3 documents' versions. This pass advances **none** ⇒ rule 4 is
satisfied by **not** re-issuing, and ⛔ **an unnecessary re-issue would itself be a defect** — it
would invalidate the 14 protected-baseline hashes and every citation keyed to the current
identifier.
